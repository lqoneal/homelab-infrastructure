# Provider and Session Runtime Assessment

Provider qualification, selection, launch, native session, Codex session, process/PID tracking, reconciliation, and supersession modules exist with focused tests. The architecture documents bind provider/session identity to mission and execution identity and require fail-closed stale/dead-process handling.

There is no completed, independently verified target-mission run proving the whole chain from admitted mission through provider launch, live session, process liveness, interruption, replacement, and resume. Existing fixtures also expose contract coupling: autonomous hydration requires an authorization receipt not present in one Stage 1 execution-resolution fixture. Classify as `HIGH / BLOCKS_SAFE_RECOVERY` until a canonical adapter or unified receipt contract is implemented and tested.
