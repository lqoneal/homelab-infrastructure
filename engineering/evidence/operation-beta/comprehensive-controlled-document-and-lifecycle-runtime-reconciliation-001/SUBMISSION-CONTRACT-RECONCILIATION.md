# Submission Contract Reconciliation

The authoritative new-work path is:

`zeus submit` → source resolution/classification → canonical provenance verification or deterministic promotion → shared P2 submission boundary → immutable submission receipt and admission request (`ADMISSION_REQUESTED`).

Canonical authored WOPs verify existing traceability. Promotable Development sources preserve source bytes, WOP identity, Mission identity, and source digest while deriving deterministic provenance. Explicit legacy packages alone use Stage 1 compatibility. `--repository` does not select the legacy path. Replay verifies the same canonical identity and does not create a duplicate mission or admission request.

This contract is represented by the prior corrective implementation and its controlled documentation. No lifecycle source bytes were changed here.
