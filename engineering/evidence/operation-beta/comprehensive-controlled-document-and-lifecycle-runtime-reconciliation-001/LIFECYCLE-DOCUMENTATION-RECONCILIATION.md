# Lifecycle Documentation Reconciliation

Current documents consistently distinguish submission from admission and later execution controls. Stage 1 owns receipt-backed intake/history; later admission, provider qualification, session, execution, evidence, publication, EOS, and closeout controls remain separate.

The documented state-machine contract describes receipt-bound transitions from source discovery through `CLOSED`, while provider launch and autonomous controller states are subordinate/derived. `DISPATCHED` requires a dispatch receipt and bound admission/execution projections; `EXECUTION_STARTED` requires an actual execution session. These are documented requirements, not a claim that the complete runtime is already end-to-end proven.

The prior corrective’s directly affected documents were preserved in the publication candidate. This handoff changed only validator/traceability documentation needed for truthful current validation; historical evidence was not rewritten.
