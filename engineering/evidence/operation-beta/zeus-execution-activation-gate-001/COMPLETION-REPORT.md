## Root cause

`bootstrap_boundary._verify_admission` counts every JSON file in each P3
artifact directory and requires each count to equal one. The durable runtime
preserves a valid historical Beta admission and now contains a valid lifecycle
admission, so the verifier reports counts of two even though the selected
admission transaction is identity-bound and valid. This conflicts with the
requirement that historical records remain immutable and coexist with current
canonical lifecycle state.

dispatch, provider selection, provider invocation, execution session,
execution start, mission work, monitoring checkpoint, publication, push, EOS
synchronization, closeout, or CAGF-01 execution was performed.
