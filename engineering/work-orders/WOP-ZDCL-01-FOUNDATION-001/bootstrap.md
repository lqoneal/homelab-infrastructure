# WOP-ZDCL-01-FOUNDATION-001 Bootstrap

## Authority

This package is the qualified preparation contract for `ZDCL-01` under the
published Operation Beta roadmap. It is bound to the canonical repository and
the development planning baseline `OB-PLAN-v1.0.0`; it does not authorize
changes to the `OA-v1.0.0` production baseline.

## Objective

Establish the bounded native Zeus development-session foundation for session
identity, classification, repository and baseline verification, and evidence
capture.

## Explicit boundaries

This WOP does not authorize implementation of ZDCL-02 or later increments,
CAGF, EPE, Operational Alpha, production changes, distributed execution,
approval interception, publication automation, or any runtime deployment.

## Verification-first execution

1. Verify repository identity, branch, clean state, and `HEAD == origin/main`.
2. Verify `OA-v1.0.0` and `OB-PLAN-v1.0.0` are unchanged and distinct.
3. Synchronize and validate EOS, Registry, MKM, EMM, PMCT, roadmap, and
   controller projections.
4. Resolve the ZDCL-01 mission object and this package digest.
5. Create a bounded session identity and classify its effect profile.
6. Verify repository and development-baseline bindings before any permitted
   development action.
7. Capture evidence for each satisfied condition and fail closed on ambiguity.
8. Reconcile evidence and close the session without changing production state.

## Approval boundary

Submission stages this WOP. Admission and execution remain separate protected
boundaries. No protected action is approved, admitted, or executed by package
submission alone.

## Interruption and recovery

Persist the session identity, resolved authority, package digest, repository
identity, baseline identity, completed verification steps, and evidence paths.
On restart, verify the persisted digest and resume only from the last qualified
checkpoint. A mismatch, stale baseline, or incomplete authority fails closed.

## Evidence and closeout

Required evidence includes authority resolution, session identity,
classification, repository/baseline verification, EOS/platform validation,
negative-boundary results, interruption/recovery result, reconciliation, and
operator acceptance. Closeout requires a completion receipt; it does not imply
implementation of future ZDCL increments.
