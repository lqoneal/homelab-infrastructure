# Filesystem Remediation Recommendation

The NTFS dirty-volume condition requires Windows-native journal and metadata
handling, but repair shall occur only after the current backup and media
content has been consolidated, verified by SHA-256 manifests, and protected in
at least two governed copies. Repair before consolidation risks changing or
orphaning engineering evidence on a device with 140 recorded reallocation
events.

Under a separately authorized repair mission, identify the volume by enclosure
serial, drive serial, exact capacity, NTFS UUID, and volume label; confirm no
dependent process is using it; capture pre-repair SMART and Windows event
evidence; run `chkdsk X: /scan` where supported; review the result; then run
`chkdsk X: /f` with exclusive access only after preservation gates pass. Do not
start with `/r`, formatting, repartitioning, forced mounting, or non-native
dirty-bit clearing. Preserve complete output, safely eject, reconnect, rerun
read-only inspection and SMART, and compare post-repair manifests. Any lost
file, bad-cluster, read, transport, or new SMART event stops reassignment.
